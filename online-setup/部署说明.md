# Supabase 联机部署

版本 12 新增游艺屋和空当接龙每日首次通关奖励。联机胜局由服务端重放初始牌序及全部移动进行校验，按北京时间每天最多发放 3 钻石，支持请求重试、跨设备防重复和同一胜局防重复提交。牌局移动保存在当前浏览器的本地存档下，跨浏览器登录不恢复进行中的纸牌布局；钻石奖励继续走账号云端同步。

版本 11 移除准备状态的断线超时，以及未出发队伍的自动过期。招募队伍跨日保留队员、编号和准备状态，目的地及领取截止时间更新到当天，出发时重新检查技能、属性和剩余时间。手动取消准备、退出或解散队伍保留。已出发远征仍须北京时间当天 24:00 前领取，跨日未领取仍失败。此前已过期的队伍不恢复。

版本 10 将收藏玩耍的心情改为消耗 15–25，其余体力、清洁、随机钻石和每日限制不变。客户端同时调整收藏馆建筑、营地登录门槛、收藏馆入馆门槛和首次建筑解锁提示；小镇显示选择仅列出馆藏宠物。

版本 9 新增收藏馆：九级宠物自动入馆，不能作为主宠物参加普通活动。联机收藏玩耍按北京时间每日一次，每只可玩宠物随机给予 1–3 钻石，当天合计最多 30；消耗 20 体力和 8–15 清洁，增加 15–25 心情，要求体力大于 20 且四项属性均不为零。服务端统一结算、防止跨设备重复领取。所有宠物入馆后允许没有主宠物，可从商店领养新宠物。更新会收录已有九级宠物，不删除宠物；已在远征中的宠物等待远征结算解除锁定。

版本 8 新增密码确认注销账号。账号、云端存档、仓库、会话、好友关系及本人创建的远征队伍会删除；队伍内其他玩家的宠物会解锁，其他账号及存档保留。本地存档解除绑定后保留。注销接口限制密码尝试次数，并支持网络丢失响应后的安全重试。

版本 7 修复 JSON 整数以 `5.0` 或科学计数法存储时触发“输入格式不正确”的兼容问题。服务端在读取旧存档、请求和配置时规范整数数值，覆盖切磋、一起玩耍、保存及远征流程；保留真正的小数和原有校验，不重置账号、存档、冷却或队伍。执行最新完整 SQL 后，部署检查应显示版本 7。

版本 6 新增好友切磋与一起玩耍，必须执行最新 `online_install.sql` 才能使用。双方主宠物的属性、经验、倾向和成长记录由服务端一次性更新。切磋公式、随机值、奖励、消耗及双向 4 小时冷却来自原插件；一起玩耍为双向 2 小时冷却。好友详情仅返回主宠物，不再返回全部宠物。更新保留已有账号、存档和队伍。

游戏客户端已接入注册、密码登录、好友、远征和共享材料。真正的在线功能需要先执行下面的 SQL；没有部署时游戏会提示联机服务尚未启用，原有本地档可以继续玩。

## 在控制台执行

1. 打开当前游戏使用的 Supabase 项目 `kuphplheznrufbpjmvgj`。
2. 进入 **SQL Editor → New query**。
3. 复制同目录 **online_install.sql** 的全部内容，粘贴并点击 **Run**。这个文件已经包含游戏与七个远征地点配置，不需要另外导入 JSON。
4. 新建查询执行：

```sql
select public.pet_online('{"op":"health"}'::jsonb);
```

应返回 `{"ok":true,"version":5}`。

5. 刷新游戏网页，进入现有存档，在“设置 → 账号与联机”填写注册名、密码和确认密码，勾选确认后注册。请记住密码；本版没有邮箱找回功能。
6. 用另一个浏览器打开游戏，先创建或进入一个本地存档，再从“设置 → 账号与联机 → 登录恢复”输入账号密码，选择恢复位置并确认。原有位置会另存到 `before_online_slot_N.json`，正常存档也继续保留 `.bak` 备份。

本安装是新增 `pet_private` 私有数据结构和 `public.pet_online` RPC，不删除已有的 `cloud_saves` 旧插件存档表。可重复执行；重新生成配置会更新后端规则，不会重置已注册账号或发放材料。

旧版升级也执行完整文件。本次新增招募状态字段，并将“同一账号只能参加一支远征”的旧索引替换为“最多一支未出发队伍”的索引；`DROP INDEX` 只移除旧限制，不删除表或存档。升级会保留正在进行的队伍与奖励记录。

版本 3 将玩家编号改为随机唯一的五位数（10000–99999）。已有的递增长编号会在升级时换成五位编号；账号、密码、存档、好友及队伍关联不变。刷新同步后显示新编号，旧长编号不再用于搜索。重复执行升级不会更换已生成的五位编号。

版本 4 调整远征记录：只显示成功出发的队伍，包含进行中、已完成未领取、已领取和跨日失败。未出发或招募超时的队伍不显示为远征记录；此次只调整查询，不删除已有数据。

版本 5 增加轻量轮询。状态没变化时只返回版本、状态摘要与服务器时间，不传存档及头像。普通操作先保存本地，停止连续操作 5 秒后合并上传，连续操作最长 30 秒也会保存一次；后台上传不锁普通操作。参战、材料、领奖会排队等待必要的存档上传并由服务端确认。未升级后端时客户端自动回退旧同步接口，仍可后台保存。

## 使用规则

- 注册名与饲主名分开，注册名忽略大小写查重；玩家编号随机生成五位数并保证唯一，不按注册顺序递增；支持注册名和编号搜索。
- 一组三个本地存档只注册一次。账号绑定的是注册时的存档；其他两个仍是本地养成档，材料仓库互通。
- 材料首次注册只导入一次。后续旧档导入、重新登录和开新档均不会重新导入材料。材料消耗由后端扣除，有幂等请求记录。
- 注册次数绑定浏览器保存的存档组标识。删除全部浏览器数据会丢失这一标识；这不是对现实中同一个人的身份认证。远征仍按服务器账号检查一个账号一个席位，不能靠切换三个存档占三个席位。
- 账号绑定存档采用版本号与三方合并同步：上传期间的新修改保留到下一次上传，不同字段的远端变更可合并。同一字段确实被其他设备改动时，本地存档另存 `online_conflict_slot_N.json`，提示后恢复服务端最新版本。`online_base.json` 保存已确认的基线，刷新后可识别本地未上传进度。
- 两个本地档的进化先确认共享材料扣除，再应用本地进化；断线会保留操作编号重试，不能通过反复点击重复扣减。
- 远征由 3–4 个不同账号参加，各自使用主宠物。准备锁定参战宠物；手动取消准备后才能换宠。招募队伍和准备状态不再因离线或跨日自动取消。
- 同一账号最多参加一支未出发队伍。已出发的远征不阻止使用另一只空闲主宠物创建或加入新队伍；同一支队伍仍只占一个席位。未准备时队伍展示当前主宠物；出发后参战宠物固定。多支远征分别计时、领取，“一键结束”收取全部已完成远征。
- 每天全服固定一个副本，北京时间 00:00 换日；消耗、技能合计、倾向、经验和材料权重取自原插件 JSON。随机掉落权重包含“空”。
- 必须当天完成且当天领取；跨日未领取失败，解除参战占用，不退还已扣属性，也不补发材料。过期处理在服务端下一次请求时执行，按服务端时间判断，不依赖浏览器是否在线。
- “一键结束”只领取已完成活动，不提前结束远征。远征结果复用现有小弹窗，各队员独立领取。

## 数据与认证实现

此版本使用 SQL 内账号和不透明会话令牌，不额外要求 Edge Function 或邮箱配置。账号在 `pet_private.accounts`，不会出现在 Supabase Auth 的 Users 列表。密码先 SHA-256 预哈希再 bcrypt，数据库只存密码哈希；会话为随机令牌，数据库只存其 SHA-256 哈希。客户端不保存密码，登录会话默认有效 30 天。

所有业务表启用 RLS，并撤销 `anon` / `authenticated` 的直接访问权限。客户端只有调用 RPC 的权限；RPC 验证会话，再检查好友关系、队伍归属、准备状态、人数、属性、技能、截止时间和唯一领取记录。客户端只使用已有的 publishable key，不需要 service_role 或数据库密码。

当前普通单机养成继续使用原有客户端计算和版本同步；共享材料、账号进化扣材、远征出发与奖励由服务端处理。普通金币/技能快照尚不是完整的防篡改游戏服务端，不应把旧本地进度当成可验证的历史流水。

## 文件与验证

- `online_schema.sql`：可维护的后端逻辑。
- `online_install.sql`：实际粘贴到控制台的完整部署文件。
- `../tools/build_online_install.py`：把游戏配置和远征 JSON 打包到安装文件，同时生成 Godot 的远征展示数据。
- `../tools/online-tests/backend.test.mjs`：在真正的 PostgreSQL WASM 运行时内验证注册、权限、准备、领取、重复请求、材料和跨日失败。
- `../game/tests/OnlineIntegrationTest.gd`：Godot 客户端经 HTTP 调用同一份 SQL，实现三账号组队和原有一键结束弹窗的集成测试。

后端配置变更后先运行生成脚本和测试，再把新的 `online_install.sql` 执行一次。
